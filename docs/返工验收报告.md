## 第 1 条 · 手机端「巡回查岗与管束」设置入口：真机上没有

**根因（已定位）**：不是运行期被 `setVisibility(GONE)`，而是 `buildMagazinePages()` 调用 `replaceScrollContent(sectionGate, guard)` 时，内部 `removeAllViews()` 把 `activity_main.xml` 里 `sectionGate` 的**全部子视图（含 `drawerPolicyButton`）整体销毁**；而动态版 `buildGuardMagazine()` 原本没有补这个入口 —— 所以真机上「守护」页第二行永远是空的。

**修复**：
- `MainActivity.buildGuardMagazine()` 在「安心规则」分组新增入口卡片：`查岗与管束 / 巡回周期、安静时段与拉回分级`，点击走 `openPolicySettings()`。
- 新增 `openPolicySettings()` 方法，跳 `PolicySettingsActivity`（Manifest 已声明）。
- 清理三处失效引用：`bindViews()` 的 `findViewById(R.id.drawerPolicyButton)`、`onCreate()` 的点击绑定、`styleDrawerButton(drawerPolicyButton, t)`（否则编译失败）。
- `activity_main.xml` 删除该失效 Button，换成注释，避免日后再次误判。

**核验证据**：
- ✅ 本地真实编译通过（已含上述清理，否则 `cannot find symbol`）。
- 📱 真机证据：运行 `verify_on_device.sh` → 第 1 步会对守护页执行 `uiautomator dump`，并 `grep "查岗与管束"`；**判定标准：dump 中存在「查岗与管束」文字 + 截图 `evidence/01_guard_page.png` 能看到该入口**，即修复成立。

## 第 3 条 · 分级拉回弹窗（先弹窗，不直接跳；拒绝留理由、进日志并上报）

**修复两个真实 bug**：
1. `PullBackCard.buildReasonDrawer()` 创建了 `reasonDrawer` 却**从未 `addView`** —— 软级点「再等一会儿」什么都不会发生，拒绝流程完全走不通。修复：把抽屉挂进视图树（默认 GONE，点按钮展开在按钮行下方）。
2. `ActivityEventStore.recordPhone()` 受 `KEY_JOURNEY_ENABLED`（记录本机轨迹开关）拦截 —— 用户关掉轨迹后，拒绝理由完全不记录不上报，与「拒绝必须留理由、进日志并上报」冲突。修复：新增不受开关影响的 `recordForced()`，接受/拒绝/忽略三条路径改用它。

**核验证据**：
- ✅ 编译通过（强级别不创建 `later` 按钮、清理冗余三元、`buildReasonDrawer` 不再接收 `strong` 参数）。
- 📱 真机证据：`verify_on_device.sh` 第 3 步采集软级/强级截图 + `logcat` 原文并 `grep "拉回|pull_back"`；**判定标准：logcat 中能看到 软/强/拒绝/忽略 四类记录；软级有两按钮且能展开拒绝抽屉，强级只有单按钮「现在就回去」无拒绝入口。**

> 沙箱内已用 Robolectric（开源免费的 JVM 级 Android 运行时）对第 3 条做了 UI 层断言（软级双按钮 + 抽屉可展开 + 理由回调、强级单按钮 + 无抽屉 + 走 onAccept、主题联动），核心用例均通过；第 3 条的真机级验收以 `verify_on_device.sh` 的截图 + logcat 原文为准。
